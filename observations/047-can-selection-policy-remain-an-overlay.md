# Observation 047 — Can Selection Policy Remain an Overlay?

## Question

Observation 046 separated two claims:

```text
there exists a covering frontier
```

and

```text
which covering frontier is selected?
```

The next question is:

> If multiple valid covers exist, does the graph itself determine a stable selected cover, or can selection policy remain a separate overlay on the same graph?

## Why Alloy

The missing question is static independence between two structures:

1. the revision graph that determines coverage;
2. a preference relation used only to select among already-valid covers.

This is the same kind of pressure that Observation 033 used to separate event history from a valuation relation. No transition semantics are needed, and there is not yet a general law worth lifting to Lean.

## Neutral model

Each world contains:

```text
known  : set Node
parent : Node -> Node
better : Node -> Node
```

`parent` determines frontier and coverage.

`better` is a strict total order over known nodes and is used only when a node has more than one valid covering frontier.

The selected cover is derived as the covering frontier with no better covering frontier above it in the policy order.

## Pressure

Use two worlds with the same graph.

The graph contains a small fork where one root has two distinct covering frontier tips.

Then ask:

1. Can different policy orders over the same graph produce different selected covers while coverage remains unchanged?
2. Does the graph alone determine selection?
3. Does graph plus the same policy determine selection?

## Expected interpretation

If the first witness is SAT, `better` can vary over the same graph while only selected identity changes.

If `GraphDeterminesCoverage` has no counterexample, coverage belongs to the graph rather than the policy.

If `GraphDeterminesSelection` has a counterexample, the graph alone does not choose among valid covers.

If `GraphPlusPolicyDeterminesSelection` has no counterexample, the pair

```text
graph + policy
```

is sufficient for the selected-cover vocabulary in this bounded world.

That would close the current chain as:

```text
existence of a cover   -> graph law
selected cover         -> graph + selection policy
```

The policy would be an additional semantic layer, not something generated by the graph merely because a choice is needed.

## Boundary

This observation does not claim that a production system needs a stored total order, nor that total order is the right policy form.

It tests only whether some explicit selection structure is distinct from the coverage graph when multiple covers are admissible.

It also does not yet add time to policy changes. That is deliberately outside this observation because the current branch is being closed after the existence / selection / selection-policy distinction is established.

## Tool choice

**Alloy only.**
