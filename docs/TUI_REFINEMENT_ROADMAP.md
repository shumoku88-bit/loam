# TUI：操作体験の洗練化と今後の課題

## この文書の目的

LOAM の TUI 改修は、ローカル・リモートを問わず、複数の AI アシスタント（Claude Code、Cursor、Copilot、Antigravity 等）や開発者が継続的に協調して進めています。

本書は、どの環境・どのアシスタントから作業する場合でも、**確立された設計原則を損なわず、目指すべき操作体験と今後の改善課題を共有するための方針文書**です。
画面ごとの具体的な進捗管理は [`docs/TUI_NON_BUDGET_WORKLIST.md`](TUI_NON_BUDGET_WORKLIST.md) を参照してください。

---

## 1. 確立されている設計原則（維持すべき基準）

LOAM の TUI はすでに強固な基礎を持っています。機能追加や改修の際にも以下の原則を必ず維持してください。

* **幾何学的な堅牢性（Bounded Layout）**:
  * 32×9 や 48×14 などの極小画面から大画面まで、ターミナルリサイズ時に絶対にクラッシュ・文字欠損・レイアウト破綻を起こさない。
  * 画面幅・高さの縮小時は、情報優先順位に従って安全に畳み・縮退表示を行う。
* **静寂と抑制（Quiet Aesthetics）**:
  * 原色や過剰な装飾ウィジェットを排し、細い丸角枠、控えめな階調（`.normal` と `.muted`）、整然とした余白で統一する。
  * 強調色（`.selected` や `.series1` など）は意図された焦点にのみ最小限で用いる。
* **異変・要確認のシグナル駆動**:
  * 平常時は画面を静かに保ち、確認事項・未完了・期限切れなどの注意が必要な時のみ、最小限のバッジや通知シグナルを出す（情報過多を防ぎ、詳細画面への誘導にとどめる）。
* **チラツキのない差分描画（Dirty Diff Rendering）**:
  * 前フレームとの差分のみをターミナルへ送出する設計を崩さず、画面遷移や再描画時のフリッカー（画面のチラつき）を発生させない。
* **固定下部ナビと予約通知行**:
  * 最下部の固定 2 段ナビゲーション（キー操作一覧）と通知行の配置・高さを一貫して維持する。

## 2. 今後の改善課題

日常の主要画面（Home, Actual, Balances, Attention, Daily Pace 等）は整っていますが、より洗練された道具にするために以下の改善課題が残されています。

### 課題 1：残存画面のトーン統一（Coverage）
* [`docs/TUI_NON_BUDGET_WORKLIST.md`](TUI_NON_BUDGET_WORKLIST.md) に記載されている未着手・検証待ち画面（Scheduled の置換・一括編集、Reports 各子画面、Settlements 等）を、現在の丸角枠・余白・固定ナビのトーンへ揃え切る。
* 新規作成画面や補助画面を浮かせず、既存の完了画面とシームレスに統一する。

### 課題 2：検索・パレットの手触り向上（Interactive Polish）
* コマンドパレット（UI-02）や Locus / 候補選択における**インクリメンタルなファジー検索（あいまい検索）**の導入。
* 入力途中でも候補が瞬時に絞り込まれ、選択移動に追従してプレビューや詳細がリアルタイムに連動する、思考を止めない軽快な操作感を整える。

### 課題 3：操作の発見しやすさ（Discoverability）
* 下部フッターに収まりきらない詳細なキーバインドやショートカットを、各画面から `?` 等で安全に確認できるヘルプオーバーレイ（which-key 的な案内表示）。
* 初見の操作でも迷わず、画面ごとの文脈に応じたキーマップを俯瞰できるようにする。

### 課題 4：端末エルゴノミクス（Terminal Ergonomics）
* トラックパッドやマウスホイールによる、詳細ペイン・一覧の自然なスクロール対応。
* OS クリップボードとの連携（コピー・貼り付けの円滑化）。
* ターミナルのカラー環境（TrueColor / 256色）に応じた配色の最適化。

## 3. 各 AI アシスタント・作業者への共通指針

TUI の改修コードを書く際は、以下のルールを遵守してください。

1. **引き算のデザインを維持する**:
   * 見た目を「派手」にするための過剰な枠やステータスバー、原色を追加しない。
   * 「表示する情報を減らし、必要な時に掘り下げられる」設計を最優先する。
2. **1 画面・1 課題ずつ確実に進める**:
   * 複数の画面や大きな機能を一度に変更せず、小さく区切って完了させる。
3. **極小画面リサイズテスト・PTY テストを必須とする**:
   * 変更を行った画面は、通常表示だけでなく 32×9 や 48×14 などの極小画面でもテストが通ることを確認する。
   * `lake test`（代表 TUI テストおよび合成 PTY テスト）がすべて通過することを確認する。
