## Clean baseline

The baseline completed **CLEAN** at the pinned revision.

It found one important premise correction: the concrete stale-root transition in
the task is not reachable through the current ordinary `CorrectionPublisher`.

Ordinary correction publication generates a fresh replacement Event id rather
than choosing an existing Event as a replacement endpoint. Therefore a previously
independent stable root does not become a replacement endpoint merely through
the ordinary correction path. Extending a correction chain changes the terminal
Event while preserving the root identity reflected by an existing anchor.

The baseline initially followed the task premise and began auditing stale-root
reader / publisher behavior. After inspecting the correction publisher's fresh
replacement identity rule, it revised the main analysis around reachability.

## Protocol lesson

A fresh chat or nominally separate session is not sufficient isolation when
inherited conversation summaries, memory, or other session context can expose the
other arm's result.

For future paired trials:

1. seal the task and both arm prompts before either run starts;
2. launch baseline and skill arm in independent contexts before either result is
   brought back to a shared evaluator;
3. do not expose either arm's result to the other arm until both runs are
   complete;
4. if either arm reports prior exposure to the other arm's result, mark the pair
   contaminated and unscored even when all repository claims are independently
   rechecked;
5. only after both arms finish should an evaluator receive both reports and make
   the Better / Same / Worse comparison.

This is a protocol mutation, not a candidate-skill mutation.
