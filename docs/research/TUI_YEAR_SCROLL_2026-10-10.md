# Year-zoom transaction input tail — 2026-10-10

Issue #1868 step 1; performance neighbor #1863. Baseline: `562c5e2d`.
This is a Home presentation repair, not the later month-label/footer redesign.

## Reproduction and diagnosis

Use only the temporary synthetic HouseholdImage generated by
`tools/benchmark-tui-resources.py`. The fixture adds the requested Events beside
one seeded completion Event. At 10,000 Events / 500 dates, the selected current
year contains 5,661 records / 16,984 detail rows on this observation date.

`tools/benchmark-home-scroll.py` opens Home, `zz` (Year), then Tab (Detail).
It writes 20 navigation events followed by an ordered Space sentinel. Time ends
when Commands is rendered and output has been quiet for 20ms. This is an
**upper-bound input-release-to-sentinel observation**, including sentinel rendering
and quiet-detection overhead, not an isolated single-event latency or a physical
wheel-device test. Home/End resets each trial. Full Home redraw after the sentinel
checks equal keyboard/wheel selection and return-to-start on direction reversal.

Distinguishing the proposed causes:

- **Queued events:** the baseline takes seconds to reach a sentinel already queued
  after the burst. Keyboard events remain individually processed; wheel packets
  already had consecutive same-direction batching. Neither policy is changed.
- **Rebuilding/queries:** Home navigation and reconciliation repeatedly expanded
  every period transaction into Widgets and recomputed prefix row lengths. Frame
  construction did it again. Wide overview counts/flow and `pendingEvidence`
  repeated history work too; the latter invokes existing Scheduled qualification
  against retained Event identities. There is **no fresh household file query in
  the local navigation branch**. All existing load/publication boundaries remain.
- **Diff/output:** the production dirty renderer is already bounded to terminal
  rows. Reusing rows without changing that renderer removes the long tail.
  The separate native probe below observes 3ms for 20 redirected diff/output
  calls, versus seconds of non-reused navigation preparation. Redirected output
  is not evidence of a real terminal's throughput.
- **Viewport/selection:** existing selection-following, wrapping, oversized record,
  focus, period, reload and Enter identity tests still pass. Prepared-vs-fresh
  cells/styles and geometry agree; no extra motion/timer state was introduced.

## Repair and lifetime

`Home.DetailLayout` is a concrete process-local projection of one immutable Home
snapshot: record array, exact row starts/counts, unselected wrapped rows, wide
calendar rows, and the existing qualified Pending answer (including refusal).
Only selected-record rows are restyled; the viewport takes bounded array slices.
No approximate row-height formula or alternate accounting calculation is used.

The Home IO loop carries this projection through local navigation and the
read-only palette. Date/zoom/width changes rebuild it; height/focus/selection
changes reuse wrapping and recompute visibility. **Every workspace return drops
it**, including canonical reload after attempted publication. Cache matching is
not an authority/freshness check: callers must never carry a layout across a
snapshot replacement. No operational files, data pins, writer checks, frontier
semantics, or unknown handling change.

executables; three rounds, milliseconds (median). OS scheduling/cache effects

After resize, `jk`, Page Down/Up and the sentinel took 223–261ms at 10k and
258–319ms at 50k for 80x24, 48x14 and 160x48. These include new-width preparation,
not just steady-state scrolling. A 24-Event / 12-date run also passed. All fixture
file digests remained identical, final selections matched, and idle output after
the sentinel/return was zero. This is not a long soak or proof of leak freedom.

CI uses a deliberately generous **2s regression budget per fixed burst** at
10k / 500 dates, one round. This detects the observed 15–30s regression while
allowing runner noise; it is not a universal product performance guarantee.

## Native phase separation

`tools/HomeScrollProfile.lean` measures **candidate** prepared/unprepared paths,
not a relinked old baseline or additive production IO phases. Three 10k / 500d
samples: initial preparation 236–240ms; 20 navigation calls without reuse
4,706–4,783ms; with reuse 1–2ms; 20 bounded frames 99–106ms; redirected diff/output
3ms. Preparation consumes the same existing qualification; reuse does not omit it.
The profiler checks geometry agreement and final cursor 20. Pure work is deferred
until after the start clock; do not substitute interpreted Lean latency claims.

```sh
lake env lean -c /tmp/loam-home-scroll-profile.c tools/HomeScrollProfile.lean
python3 - <<'PY'
import importlib.util, shlex, subprocess, tempfile
from pathlib import Path
args = [a for a in shlex.split(Path('.lake/build/bin/loamTui.rsp').read_text())
        if not a.endswith('/Loam/Tui/Executable.c.o.export')]
subprocess.run(['lake', 'env', 'leanc', '-O3', '-o', '/tmp/loam-home-scroll-profile',
                '/tmp/loam-home-scroll-profile.c', *args], check=True)
spec = importlib.util.spec_from_file_location('probe', 'tools/benchmark-tui-resources.py')
probe = importlib.util.module_from_spec(spec)
spec.loader.exec_module(probe)
with tempfile.TemporaryDirectory(prefix='loam-home-phase-') as tmp:
    root = Path(tmp) / 'synthetic'
    probe.fixture(root, 10000, 500)
    before = probe.digest(root)
    for _ in range(3):
        subprocess.run(['/tmp/loam-home-scroll-profile', str(root)],
                       check=True, stdout=subprocess.DEVNULL)
    assert probe.digest(root) == before
PY
```
