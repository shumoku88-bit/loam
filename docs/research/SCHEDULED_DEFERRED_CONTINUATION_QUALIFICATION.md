# Scheduled deferred continuation — issue #1053 qualification

Status: **MINIMAL PRODUCT SLICE UNDER QUALIFICATION**

## Household gap

After one Scheduled occurrence is completed, LOAM already:

- reloads current-open Scheduled evidence;
- surfaces a later similar plan when one is explicitly retained;
- offers ordinary Scheduled creation when the user wants another occurrence.

The remaining ambiguous no-candidate branch was:

```text
Done
Add next
```

`Done` could mean either:

- continuation intentionally ends here; or
- continuation remains undecided and should be remembered for later.

Elapsed time cannot distinguish those worlds without inventing recurrence semantics.

## Smallest candidate

Change only the no-candidate prompt to:

```text
Done
Defer
Add next
```

Semantics:

- **Done**: write nothing, preserving the current default and Escape behavior;
- **Defer**: retain one ordinary Attention item;
- **Add next**: use the existing Scheduled creation path.

When a later similar current-open Scheduled already exists, the existing
`Keep as is / Add another / Review` prompt remains unchanged. Explicit retained
future evidence already prevents the silent loss that #1053 is about.

## Deferred evidence

The Defer path uses:

```text
ScheduledContinuationSession
  -> HouseholdCommand.addAttention
  -> AttentionPublisher
  -> attention.loam
```

The retained Attention has:

```text
context = human-readable completed Scheduled identity + summary
due     = dueUndetermined
```

`dueUndetermined` is deliberate. The user has said that a household matter
should remain visible, but has not said when continuation should be decided.

It must not be rewritten as `noDueDate`, and no next Scheduled date is inferred.

## What is not retained

This slice adds no:

- recurrence;
- series identity;
- continuation relation;
- next date;
- cadence;
- frequency;
- automatic Scheduled creation;
- second task/attention authority;
- parser for Attention context.

The Attention context is opaque human context under the existing Attention model.
No code is allowed to reconstruct a Scheduled relation by parsing that text.

## Failure behavior

Scheduled completion has already succeeded before the continuation prompt runs.

Therefore if Attention publication for Defer is refused:

```text
completion remains published
+
deferred intent was not retained
+
explicit refusal notice is returned
```

The implementation does not roll back completion or fabricate an Attention item.

## Why this stays TUI-local for now

Issue #711 tracks a future frontend-neutral tool boundary. Current evidence does
not yet show that "defer Scheduled continuation" is a shared product command used
by multiple frontends.

So this slice keeps the orchestration in
`Tui.ScheduledContinuationSession`, while durable mutation still delegates to
the shared `HouseholdCommand.addAttention` boundary.

If a second frontend later needs the same action, that is evidence to graduate the
smallest presentation-neutral command then, rather than speculatively now.

## Qualification

Focused tests must establish:

1. existing-candidate prompt remains Keep / Add / Review;
2. no-candidate default remains Done;
3. Defer requires explicit selection;
4. Add next remains explicitly reachable;
5. deferred draft uses `dueUndetermined`;
6. human context retains the completed Scheduled identity/summary;
7. actual publication creates a current-open Attention item readable through
   `AttentionReview`;
8. no Scheduled publication is performed by the Defer path.

The DRAKON execution/refusal map is generated by
`docs/drakon/build_scheduled_deferred_continuation_audit_map.py`.

## Home visibility

Issue #1053 mentions rediscovery through Attention/Home. Current production has a
qualified `Attention / Manage` surface but Home does not presently project
Attention.

This slice therefore qualifies **durable rediscovery through Attention** only.
Adding an Attention summary to Home is a separate presentation question and is
not required to make the deferred intent durable.

## Decision rule

Keep this slice if focused continuation/Attention tests and full Production TUI
qualification stay green.

If real use shows that opaque Attention context is insufficient because the
system itself must later act on the source Scheduled identity, reopen the semantic
question explicitly. Do not silently turn the human context string into a
machine-readable continuation relation.
