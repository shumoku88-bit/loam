# 非予算の家計管理：TUI 作業リスト

## 今の目的

**予算管理を使わず、日々の家計管理を LOAM で試す。**
Actual・Scheduled・Record で確認できた、控えめな色、細い枠、整列、安定した
フォーカスと操作ナビを、必要な非予算の画面にも丁寧に展開する。

この一覧は作業順と試用の問題を管理するためのもの。新しい家庭内の意味や
データ権限を定義せず、全機能の完成や実運用での問題不存在を保証しない。
現行の画面契約は [TUI.md](TUI.md)、データの扱いは
[HOUSEHOLD_OPERATING_MODE.md](HOUSEHOLD_OPERATING_MODE.md) を参照する。
研究の過去の TODO を、そのまま現在の実装待ちに数えない。

初回棚卸しのコード基準：`4d9d261b`。

## 対象と保留

- **対象**：記録・実績の閲覧と修正、明示的な予定、残高、非予算の収支・推移、
  必要に応じて Attention、精算、外貨交換、Locus 設定、実数量の観測。
- **今回保留**：Budget / current cycle、Capacity の割当・移動・再配分、
  Cycle Grant、Actual / Scheduled の Purpose routing、Reports の Budget Window。
- Daily Pace は現行の周期・支援設定への依存を個別確認するまで試用必須にしない。
  Scheduled の監視用 Pace と実際の予定日も別物として扱う。
- 予算機能や既存データを削除しない。「使わない／改善を後回し」と
  「メニューから隠す／ロードしない」は別の変更。後者はまだ実装していない。
- 予算設定なしでの起動・基本操作が成立するかは、下の `NB-01` で確認する。
  コードに依存があれば具体的な阻害箇所として記録し、推測で独立性を宣言しない。

### NB-01：最初の横断確認

- [ ] 予算の設定・割当・routing を使わない合成 household の開始条件を明示する。
- [ ] 起動し、Home から Record / Actual / Balances に入って戻れる。
- [ ] 合成の支出・収入・移動を明示的に記録し、数量・Measure・日付が正しく表示される。
- [ ] 誤入力は拒否される。Preview・キャンセル・閲覧・リサイズだけでは記録が増えない。
- [ ] 明示的な Publish の後で、一覧・詳細・残高が新しい証拠を読む。
- [ ] 修正・日付修正・reversal をそれぞれ確認し、元の履歴を失わない。
- [ ] 予算・Pace・分類等の任意情報が不足しても、成立している基本の家計回答を隠さない。
- [ ] 阻害がなければ、このループから試用を始める。全画面の統一完了は開始条件にしない。

予定の支払管理を最初から使う場合は、NB-07 の完了導線を P0 に上げ、
明示的な予定の作成 → Actual として完了 → 一覧・残高の再確認も追加する。

## 各項目を完了にする条件

1. 対象と対象外を明記し、小さな一貫した単位で変更する。
2. 控えめなパレット、整列・余白・階層、可視範囲に合ったフォーカス・スクロール・
   リサイズ、固定ナビ／通知を確認する。
3. 長い日本語、巨大な数量、複数 Measure、空・不明・読込失敗を必要な範囲で試す。
4. 書込み画面は対象と結果を明示し、キャンセル・拒否・成功後の再読込を確認する。
   履歴や admission / publication の境界を表示の都合で変えない。
5. 関連 Lean・合成 PTY テストを通し、`docs/TUI.md` とこの一覧を更新して commit する。
6. 実 household の閲覧・書込み・設定変更は、この改善テストと分けて扱う。

まだ、この一覧には試用由来の新規問題を登録していない。
実用上の問題を見つけたら、次の形で追加する。pit は既存項目との重複を確認する。

| ID | 状態 | 再現操作・困ったこと | 家計への影響 | 次の対応・検証・commit |
| --- | --- | --- | --- | --- |

状態は `未着手 / 調査中 / 作業中 / 検証待ち / 完了 / 保留`。
家計への影響は、読みづらさ、導線の迷い、操作不能、誤記録リスク、データ不整合を分ける。
各 commit で対応 ID と検証結果を更新し、必要なら上の優先順位に反映する。
