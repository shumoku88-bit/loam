# Observation 195 — semantic result observation

Observation 194 showed that the same real future Correction can leave one world with `none` and another with `some 0` at the existing fail-closed `CorrectionFrontier` projection.

The next question was whether this earns a new mathematical result type or quotient layer.

It does not.

Observation 191 already allows each observable to have an arbitrary result type. Observation 192 likewise accepts an arbitrary answer type. Therefore an observer returning `Option Answer`, `Except Refusal Answer`, or another explicit semantic-result type fits the existing observational quotient and future-context equivalence unchanged.

This observation makes the information boundary explicit for the actual `Option` shape used by CorrectionFrontier:

```text
exact semantic result
  some value / none
        |
        | Option.isSome
        v
semantic availability
  true / false
```

Lean proves:

- availability factors through the observational quotient induced by exact semantic results;
- therefore availability belongs to the Observation-191 all-endomap closure generated by exact results;
- exact future-context equivalence on `Option` answers automatically implies future availability equivalence;
- one future availability difference is enough to refute exact future-context equivalence;
- availability alone is strictly weaker than exact result: `some 100` and `some 120` have the same availability but remain different exact results.

So Observations 193 and 194 are two faces of the same semantic-result quotient:

```text
Observation 193: some 100 != some 120
Observation 194: none     != some 0
```

No special partial-equivalence or failure quotient is needed. The full semantic result is simply the observation value.

## Boundary

This observation does not add a production `SemanticResult` type and does not assign household meaning to refusal reasons. `CorrectionFrontier` currently exposes `Option`, so all refusal causes are intentionally collapsed at that API boundary.

If refusal reasons later become observably meaningful, a richer codomain such as `Except Refusal Answer` can use the same Observation-191/192 machinery. That future possibility does not justify changing production semantics now.

No production Core, Application, Persistence, CLI, TUI, manifest authority, persistence format, or household data changes are made.
